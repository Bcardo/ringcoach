# Three-tab navigation and contextual history

Implements the owner's approved #41 proposal; inline training placement is a first portion of #69. Primary navigation is Today, Training and Journal. Stored history is retained; removing a primary navigation item does not delete or migrate facts, advice, provenance or source observations.

- Today keeps the daily-focus/intake/night cards. `查看恢复趋势` opens the existing 7/30-day recovery view with date selection; `返回今日`/Back returns to Today. A selected date can open its past Journal/advice under Journal.
- Training keeps the complete day/exercise groups and current advice. When actual performance exists, the saved imported reference is now also visible with its date rather than disappearing behind the actual. `查看过往表现` expands up to three earlier recorded dates for that exact exercise, preserving all sets/partial labels within each included date. References remain references, not automatically prescribed next-session targets. No workout/day/rotation/progression is inferred.
- Journal keeps the single composer and dated corrections. `查看以往日志与建议` opens the previous records/advice view. Selecting a date loads all its saved advice independently of the overview pagination. `返回日志`/Back returns to the composer without changing its date, text, submission identity or attachment list. The composer date field state is kept outside the detail route so incomplete date input survives route changes.

Old restored `history` state maps to `journal_archive`; obsolete/unknown routes return to Today. Detail screens keep their owning primary tab selected. Settings/diagnostics retain their existing back behavior. Archive/date inspection never calls `journal.openDay`, submits progress or regenerates advice. Existing date-specific pending/status/retry semantics remain.

Exercise history is a UI-only local query with a bounded date count. Only completed/partial rows whose current journal revision matches or still contains the supporting evidence are eligible. Future dates and other exercise names are excluded; accepted corrections replace old facts through the existing extraction contract. An expanded history cache is invalidated on source reload, and old asynchronous results cannot overwrite a newer epoch. No new raw trace retention, network/provider call, prompt/request/schema, worker/collector or database-schema change.
