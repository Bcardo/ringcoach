# Journal supplements and submission feedback

Supplement entry uses the existing dated Journal composer. Report the name, actual amount/unit and time when known; planned, taken, skipped and retracted events remain distinct. The selected journal date is the event date. If a statement concerns a different date, select that date rather than expecting the extractor to guess.

Incremental nutrition extraction returns source-linked supplement events alongside food facts. Each event has a stable ID, date, quoted evidence, source submission IDs, reported amount/unit, optional reported time, status and optional food link. Unknown dose/time stays null. Corrections retain the original ID and append the new submission ID; retractions retain a tombstone rather than deleting provenance. Repeated descriptions of the same intake should preserve the existing event. Extraction remains model based; ambiguous statements can require clarification in Journal.

Protein powder and other caloric supplements remain food. A taken supplement can reference its corresponding food fact; only food facts contribute to nutrient totals. Supplement records do not add nutrients a second time. Products with uncertain composition retain unknown nutrients rather than defaulting all supplements to zero calories. Ordinary supplement additions must preserve previously converted food facts.

The confirmed standing plan comes exclusively from the owner's saved routine, diet plan and instructions in Settings. It is sent separately as that original text. This slice adds no automatic routine inference or separate structured regimen editor. A one-off Journal mention and generated advice never update Settings. Longer-lived inspectable coaching memory remains issue #40.

Events persist in immutable extraction-turn results and confirmed daily state in private journal SQLite, independently of coach prose. Existing results without supplement fields decode as an empty list; this upgrade does not retrospectively extract every old journal. Coaching receives seven calendar days ending on its request date, including per-day extraction status, events and the saved plan. Older events remain stored but are not all sent. The 30-day recovery chart range is separate from this coaching window.

Schema 12 adds a durable coaching queue. A new incremental journal submission, nutrition job and coaching queue row commit together. Each queued submission uses its own ID for the saved coach card; a card completes only that queue entry. Pending entries survive process death and work across historical dates. Pre-upgrade submissions already covered by saved cards are not replayed. Entries are processed in submission order after the relevant nutrition/workout extraction is complete; failures remain pending for the existing retry action. Each request contains its triggering submission and the latest confirmed context for that date, so a recovered backlog can include later corrections already confirmed for the same day. It does not pretend to reconstruct an earlier point-in-time state.

Today and Training label prior advice while feedback is pending. Each successful queued model response is saved as a separate card. Similar wording can still be appropriate; a new card and its source-linked input snapshot demonstrate a fresh request, not a required plan change. Food/recovery associations do not establish supplement effectiveness or causation.

Validation uses JVM parser/payload tests, disposable on-device database migration/rollback/retry tests and an opt-in synthetic live extraction/feedback test. Synthetic data is never written into the owner journal. Test classes: `SupplementEventTest`, `SupplementFeedbackStoreTest`, `SupplementFeedbackLiveTest` (`-e live_supplements true`).

November 12, 2026 validation: build and 51 JVM tests passed; 45 isolated phone storage/history/nutrition checks and the four-tab navigation smoke test passed. The owner database upgraded to schema 12 with previous nutrition values matching and zero retained bytes in released photo inputs. The synthetic live flow verified six separately generated/saved feedback cards for actual/planned intake, a repeated mention, mixed protein-powder/workout input, dose correction/explicit skip, a new supplement with unknown dose, and a retraction. Broader unfolded/large-text navigation checks and unattended multi-night recovery acceptance remain separate roadmap work.
